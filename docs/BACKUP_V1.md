# 文本备份 v1 合同

文件扩展名建议 `.xuaney.json`，UTF-8 JSON，最大 8 MiB（整个文件）。无压缩、无目录解包、无外部附件引用，因此不执行路径提取、SQL、脚本或 URI 中的代码。

外层字段必须完整且无未知字段：`format = XuaneyNote.text-backup`、`version = 1`、`payload_bytes`、`sha256`、`payload`。payload 是原始内层 JSON 的字符串；哈希是该字符串解码后 UTF-8 字节的 SHA-256，小写十六进制；payload_bytes 是同一字节串长度。不是哈希外层缩进或字段排序，不使用哈希作为密码保护或签名。

内层必须含 `app_version`、`database_version = 1`、`exported_at`、`theme`、`attachments = []`、`notes`。本版仅有 NOTE；附加任何非空附件清单、未知类型/版本、重复 ID 均拒绝，不能默默丢弃新版本数据。主题为 SYSTEM / LIGHT / DARK；临时选中笔记 ID 不参与跨设备恢复。

每条笔记包含：`id`（规范小写 UUID）、`type = NOTE`、`title`、`body`、`created_at`、`updated_at`、`revision`、`body_format`（plain / markdown）、`body_version = 1`。时间为非负 UTC Unix 毫秒，修改时间不早于创建时间；修订为非负整数。最多 10,000 条，标题最多 500 个 UTF-16 单元，正文最多 1,000,000 个 UTF-16 单元。这些是安全上限，不是万条性能已经验收。

导出在一致性快照后编码，目标关闭后读回并验证；取消文件选择不会声称成功，写入失败可能留下不完整目标文件，必须重新导出，不能将其当成有效备份。已有本地数据不因导出失败被删除。

恢复完整验证后才向用户展示确认。笔记数据库事务全部成功才提交；同 ID 同内容跳过，同 ID 不同内容生成稳定派生 ID 的“恢复副本”。再次导入相同备份会跳过已有的相同副本；用户后来修改过的副本继续保留，必要时创建另一份副本。稳定 UUID 是去重手段，不是安全身份认证。

主题在笔记事务之后更新；失败单独报告并允许重试。空间不足、校验失败、未知格式和取消不清空原库。PR-B 新增实体/附件时必须同时升级备份与恢复合同。


### PR-B B2 阶段的临时回收站保护

旧版 JSON v1 没有 `deletedAt` 字段，也没有回收站语义；因此 **当回收站非空时拒绝新的 v1 导出**，清楚告知用户先恢复希望保留的笔记。绝不以仅导出活动笔记冒充整库备份，也不要求用户通过永久删除资料解决导出问题。完整含回收站状态的备份留给 B4 v2 合同。B3.1 建立的附件元数据表一旦存在非空记录，v1 导出同样必须明确拒绝，不可遗漏图片或隐瞒其存在。

导入既有 v1 JSON 保持兼容；如果某条备份笔记在回收站存在同 ID，原条目继续留在回收站，同时生成确定性“恢复副本”，重复导入不会不断生成新副本。导出/导入失败均不得清空原笔记。

备份是**明文**。系统文件选择器可能提供第三方云盘；用户选择该提供者时由其处理文件。应用不自动上传，也不能控制外部提供者或系统输入法。
