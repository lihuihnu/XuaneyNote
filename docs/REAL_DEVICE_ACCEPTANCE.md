# XuaneyNote PR-A：真实设备验收清单

**前提**：仅使用可信下载来源取得 `io.github.lihuihnu.xuaneynote.debug` 测试 APK，核对随包提供的 SHA-256 和签名证书指纹。使用**隔离的测试数据**，避免在这版开发预览保存任何重要资料的唯一副本。

## 1. 下载、校验、安装

确认测试包对应的源码 SHA、CI run/attempt、APK 的 SHA-256 与签名证书 SHA-256，版本 `0.1.0-pr-a-debug`；安装到 Android 8.0/API26 以上的真实设备。推荐 USB/ADB：`adb install <测试APK>`。如 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，说明历史调试证书不同，**先从旧版本导出测试笔记并核对文件**，不要为了安装直接覆盖/删除用户资料。

下载后校验：Linux 用 `sha256sum <APK>`；macOS 用 `shasum -a 256 <APK>`；PowerShell 用 `Get-FileHash <APK> -Algorithm SHA256`。安卓设备通过系统文件管理器安装时，仅对可信文件来源临时允许“安装未知应用”，完成后可关闭该权限。

## 2. 设备清单

手机和平板（或至少具有足够宽度的实体 Android 平板/分屏模式），记录厂商型号、系统版本/API、分辨率、显示缩放、是否使用实体键盘及应用安装 SHA。各自重新启动应用、确认初始**无假数据、无登录、飞行模式可工作**。

## 3. 笔记和独立进程恢复

- [ ] 新建标题为“中文输入测试”的笔记，正文输入中文、英文、Emoji、换行和较长内容；观察输入法组合态、候选词与光标，等待明确“已保存”。
- [ ] 切换笔记或返回列表、退出应用后重新打开；确认文本、标题与上次选中记录一致，没有重复空白笔记。
- [ ] 使用 `adb shell am force-stop io.github.lihuihnu.xuaneynote.debug`（**不能运行 `pm clear`**），手动重新打开；确认之前**已经显示已保存**的正文仍在数据库里。
- [ ] 连续编辑、切换横竖屏与手机/平板窄宽窗口；确认列表与正文不会互相覆盖，进程重启前后实际数据一致。
- [ ] 切换明暗主题，确认设置重开后仍保持一致；提升字体/显示缩放并尝试 TalkBack，观察按钮朗读、焦点、对比度及可点区域。

## 4. 真实系统文件选择器 SAF 备份与恢复

这里必须用真实 Android 系统文件界面操作，纯 Room/Codec 单元测试不能代替。备份 JSON **明文未加密**，仅导出测试笔记和主题，请选择设备本地的 Documents/Download 文件夹，勿上传个人资料。

- [ ] 在应用设置中选择“导出”，通过 Android `CreateDocument` 创建 `.json`，确认文件写完关闭、目录实际可找到、文件大小大于 0 且能读取。记录文件实际哈希。
- [ ] 在**隔离的测试笔记数据库**中修改已导出的那条笔记，并新增另一条测试笔记；保留原导出 JSON 的独立副本。
- [ ] 从应用的“导入/恢复”启动真实 `OpenDocument`，选中上述 JSON；确认预检、用户确认与事务恢复，旧笔记没有被静默覆盖：出现冲突副本、原修改保留。
- [ ] 再导入同一份 JSON，确认不会对已经恢复且未修改的内容反复制造副本；退出/强制终止重开，检查恢复后的全部内容。
- [ ] 选择明显无效或截断的 JSON，确认拒绝导入，原数据库毫无破坏；取消文件选择器时也不产生新笔记或误报成功。
- [ ] 记录恢复冲突数、跳过数、实际笔记数量；失败时保留**不含真实私密文字**的日志、UI 截图与异常步骤。

## 5. 问题记录与结论

将以下信息按手机/平板逐项记录：设备型号、Android 版本/API、测试 APK 的 SHA-256、测试日期、每条 PASS/FAIL、失败复现步骤与非敏感截图/日志。记录真实可观察的启动、滚动和输入卡顿，**没有性能实测不填写猜测的毫秒数**。

**PR-A 只有真实设备验收通过且维护者审阅后，才能由 Draft 转为 Ready 并合并。** 测试 APK 交付本身不意味着 V1 正式发布。
