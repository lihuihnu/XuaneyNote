## 实际范围

四个 Gradle 模块为 `app`、`core:model`、`core:data`、`core:designsystem`。入口为 `MainActivity → NoteApp → NotesViewModel`；应用容器持有 `LocalData` 和应用作用域 `AutosaveQueue`。UI 不直接访问 Room；正文、格式版本、UTC 毫秒时间、修订号落入独立字段。笔记列表仅查询标题和 100 字预览，不随滚动加载全部正文。

手机单栏，实际窗口宽度达到 840 dp 时显示导航栏、列表和编辑器双栏；不根据设备型号写死“平板”。今日显示真实最近记录；记录提供创建和编辑。专注与手账入口禁用并标明待开放。没有示例笔记入库、账号或联网资源。

编辑器保留 `TextFieldValue` 的输入法组合态，旋转时 Bundle 仅保存光标位置、选中 ID，不塞入完整长正文。正文由 ViewModel 与已提交数据库恢复；系统强制终止之前尚未完成提交的极短窗口不保证零丢字。

## 保存语义

输入即时更新界面，350 ms 合并窗口，连续输入最长 1500 ms 发起一次检查点写入。单消费者顺序提交，不取消进行中的 Room 事务。更旧修订完成时不能把较新草稿标为已保存。失败保留内存草稿并显示重试入口；切换笔记、退出编辑、备份和恢复之前等待写入屏障，失败时不悄悄丢弃。

`onStop` 只是补充提前 flush，不能作为唯一保存手段。Room 成功返回才显示已保存；新建空笔记也先真实插入数据库。重开默认选中上次笔记；完整正文不放入 DataStore。没有破坏性迁移兜底。

## 基础备份

用户主动使用 SAF 选择文件，不申请广泛存储权限。导出取 Room 一致快照，带格式、数据库/应用版本、导出时间、主题、SHA-256；写入关闭后重新读取验证。恢复先完整解析、大小/数量/类型/ID/哈希验证，再确认、事务提交。冲突保留副本，重复导入不重复生成未修改副本。

Room 与 DataStore 不是一个跨存储事务。笔记原子恢复成功但主题写入失败时，明确提示“笔记已恢复，主题失败”，允许幂等重试；不宣称所有设置与笔记一起原子提交。备份未加密，哈希用于损坏检测而非身份认证。详见 BACKUP_V1.md。
