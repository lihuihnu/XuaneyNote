## 1. 本阶段的交付定义

**使用户能安全地管理和迁移长期保存的本地笔记资料。** 用户应能搜到中文笔记、误删后恢复、明确永久删除、加入图片，并将笔记/图片/回收站状态/主题一起备份、校验、导入。密码保护备份是本阶段的明确交付目标，不得以“明文 ZIP + SHA-256”冒充加密。

整个过程维持 PR-A 的可用功能与本地承诺：**完全离线、免费、无需账号、无运行时联网权限、无云备份/埋点/广告，不默认上传。** 页面精简、输入顺滑、长耗时 I/O 不在 UI 线程。拒绝任何 `fallbackToDestructiveMigration` 或“恢复失败后清空原数据库”的捷径。

本阶段验收目标是“可以在已覆盖的测试设备/系统上保存真实资料”，**不是**形式上完成页面、宣称绝对无丢字/物理擦除、发布正式 V1，也不等于已覆盖全部厂商 ROM。

## 2. 冻结功能（必须全部闭环）

| 子阶段 | 功能范围 | 用户可观察结果 |

| B0 | Room v1→v2 显式迁移、兼容旧笔记和现有自动保存 | 覆盖安装后旧标题、正文、时间、修订号、ID、主题不丢；旧 v1 备份仍可导入 |
| B1 | 中文标题/正文搜索、英文搜索；列表过滤及空结果提示 | 输入连续中文或英文可以找到正确笔记；默认不搜索回收站 |

| B3 | 图片附件（JPEG/PNG/WebP）、缩略图、独立私有文件存储 | 可以从系统选择器导入图片并离线查看；重开不丢失；异常文件不破坏笔记 |

## 3. 数据模型与数据库迁移合同

1. **保留 PR-A `notes` 表及其现有字段的身份和语义**，不重新生成 ID、不重写已有正文、不修改旧 `createdAt`、`updatedAt`、`revision`，不改变 v1 正文格式。数据库版本由 `1` 显式升级为 `2`，只在变更确实需要时增加新表/字段。
2. 增加可空的 `deletedAt: Long?`（UTC epoch 毫秒）作为软删除状态；`null` 为正常笔记。默认列表、搜索、最近记录均过滤已软删除项；回收站单独查询。恢复清除 `deletedAt`；永久删除需删除笔记及其关联，并保障共享附件安全。
3. 附件不存成 Room BLOB 或正文中的临时 `content://` URI。新增独立 `attachments` 元数据（稳定 ID、相对路径、检测到的 MIME、原始字节数、SHA-256、创建时间、可选展示尺寸）和 `note_attachments` 关联（note ID、attachment ID、排序位置），使用外键/唯一约束和必要索引。共享附件按实际引用判断清理，不猜测引用计数。
4. 新建数据模型只为当前笔记服务，不在本阶段强行将全部数据迁为 DIARY/TASK/JOURNAL 统一总表；保留未来扩展空间。使用独立的 schema 变更/迁移说明，不以文档伪造 Room `identityHash`。
5. Room 通过 **显式 `Migration(1, 2)`** 执行，保留真实生成的 v1 schema 作为历史基线，并提交工具实际生成的 v2 schema。必须用从 v1 schema 实际构建的旧库执行升级测试，再核对每个字段、索引和数据。无破坏性迁移退路。
6. 新增字段、软删除和附件不破坏 PR-A 单消费者自动保存语义。写入中的旧修订不能复活已删除笔记，也不能覆盖恢复/新版本操作；删除和恢复时先等待/协调保存屏障，失败显式报告。

## 4. 搜索与回收站合同

- 第一版采用参数化查询与中文**连续子串匹配**，覆盖标题和正文；`%`、`_`、转义字符按字面处理，防止 SQL 通配符造成假结果。保留原始正文，不因搜索归一化改写用户文字。输入端短延迟合并、取消旧 UI 请求，结果按修改时间及 ID 稳定排序，限制加载量，不对列表每项执行额外正文查询。
- 在 100、1,000、10,000 条**合成**数据中测试中文、英文、空串、特殊字符、无命中、修改、软删除和恢复；测量查询与列表响应的实际耗时/内存。10,000 条数据的搜索响应以 P95 ≤ 250ms 为**初始待验证预算**，明确记录设备和条件。若未达标，先分析 SQL 查询计划，再决定是否增加可重建的索引或 n-gram；不能声称普通 SQLite FTS 已正确解决中文分词。
- 用户删除进入回收站，**不启用自动清空**。回收站支持查看、单条恢复和明确的永久删除确认；空列表/失败提示可见。永久删除不可对其他笔记共用的附件做误删；已导出的外部备份不受应用删除控制；“永久删除”不宣称可证明的闪存物理擦除。
- 永久删除数据库事务和文件系统删除无法天然同事务：先更新受控元数据/待清理记录，提交后幂等清理文件；中断重启继续校验引用再清理。失败不提示“已物理擦除”，不会把残留文件错误地重新关联到无关笔记。

## 5. 图片存储与安全合同

- 仅支持本地 JPEG、PNG、WebP 图片；通过系统 Photo Picker（可用时）或 SAF 选择，不申请广泛存储和网络权限。不信任文件扩展名/声明 MIME：检查文件头和实际可解码性，拒绝无效或超限输入。
- **初始预算**：每原始图片 ≤20 MiB；每次备份压缩文件 ≤256 MiB、展开总数据 ≤512 MiB。额度须由实施阶段验证设备内存/磁盘路径，超限必须给出可理解错误，**不能因超限删除已存资料**。图片数量、压缩比、ZIP 条目数另设有界检查，避免压缩炸弹。
- 复制到应用私有目录中的唯一受控文件，经临时文件、流式 SHA-256、校验、落盘及数据库关联完成；失败/取消移除本次暂存，不触碰既有附件。路径只保存相对路径，阻止 `..`、绝对路径、软链接逃逸；不得保存长期依赖的外部 picker URI。
- 缩略图异步生成、按展示尺寸解码并限制缓存/内存，不在主线程读取整张原图。共享内容需持久保存单一可靠引用关系，避免删除一篇笔记误伤其他笔记的图片。
- 保留原图 EXIF 信息的风险需要在界面/说明中诚实告知；本阶段不擅自声称自动抹除定位元数据。图片与缩略图都禁止遥测上传。

## 6. 备份 v2 合同（新增前向格式，不覆盖 v1）

- **v1**：继续读取既有 `XuaneyNote.text-backup` / version 1 明文 JSON；原始导入与冲突保留语义不回退。若 PR-B 引入新数据，v1 导出不得默默丢掉图片/回收站内容：升级后默认导出 v2。
- **v2**：采用可检查的 ZIP 容器（建议扩展名 `.xuaney.zip`），根目录只有 `manifest.json`、`notes.json`、`attachments/<sha256>` 等明确白名单条目。manifest 含 `format = XuaneyNote.bundle-backup`、`version = 2`、备份时间、原应用/DB 版本、主题、笔记与附件数量、字节数、逐条目 SHA-256/引用清单及格式限制。笔记记录保存稳定 ID/标题/正文/时间/修订/格式及软删除状态；附件只按已验证清单引用。
- 导出以一致数据快照与稳定的附件引用为基础，写入可取消、流式处理；关闭目标后读回校验。SAF 目标文件写入失败可能留下不完整文件，UI 不误报成功；不自动上传。可选择本地存储位置，用户明确选择第三方存储提供方属于用户操作。
- 导入先检查 ZIP 目录、版本、所有条目名称、条目数、重复路径、压缩/解压大小、哈希、图片内容及关联完整性，阻止路径穿越和 ZIP bomb；再在私有暂存区准备文件、提供**预览与确认**，最后提交数据库事务并完成附件就绪标记。任何校验失败、取消、空间不足、进程中断均保留原有笔记和附件；启动时可幂等清理孤儿暂存。
- 相同内容幂等跳过；同 ID 不同内容保留冲突副本并保持图片与笔记的正确关联；重复导入相同备份不会不断产生副本。恢复回收站状态遵守导入选项并在确认页明确告知。Room 与 DataStore 不是跨存储原子事务；主题写入失败独立报告且可重试，不宣称“所有设置一次原子提交”。
- 不得加载整份 256 MiB 备份或所有原图进内存。旧格式与新格式均必须有不可变的脱敏/合成回归夹具，不能拿用户真实私人笔记做公共 CI。

## 7. 密码保护合同与库评审闸门

- 必须提供**用户可选**的加密备份；密码不自动上传、不持久化、不打印日志，也不放入截图或测试证据。加密备份必须保护文本、图片和主题；明文导出继续标示风险。
- 首选审阅成熟、Android 可用的 [Zip4j](https://github.com/srikanth-lingala/zip4j) 的 **AES-256 ZIP** 模式，使用其既有标准容器能力，不编写自创加密算法/密钥派生/加密 ZIP 头；不允许弱 ZipCrypto。**这里冻结安全要求和候选路线，而不是宣称已经选定并验证具体版本**。
- 实际引入依赖前必须单独完成版本锁定、许可证、安全公告、Android API26 兼容、密码字符编码、与独立 ZIP 工具的互操作及认证/错误检测评审。不得将 SHA-256 完整性校验等同于抗篡改认证；若候选方案未通过，则暂停 B5 并以同等成熟且经审阅的标准容器替换，不能使用自制方案冒进。
- 必须覆盖正确密码、错误密码、空密码、Unicode 密码、截断/篡改加密包、明文/加密格式识别、取消及进程中断。密码遗失不能由无账号本地应用“找回”。恢复成功与否必须以完整验证及提交为准。

## 8. UI 与设备交互验收

- 手机维持单栏，宽度 ≥840dp 的平板维持列表/编辑双栏；新增搜索入口、回收站入口、编辑器图片选择/展示、备份格式/密码选择及恢复预检确认。操作入口清楚，不将高级控件压进首屏。
- 真正处理中文输入组合态、长笔记光标与撤销/选区；图片选择后用户可见写入进度、成功或失败，出错时不损坏笔记文字。
- 明暗主题、大字体、TalkBack 基本标签、键盘遮挡、横竖屏/分屏及系统文件选择器一并回归。所有可用动作的触控目标按原设计 ≥48dp。
- 仅显示实际存在数据；所有自动化与截图用隔离合成数据，不把测试内容注入生产首次安装。

## 9. 不在本 PR 的范围

本阶段不实现番茄钟、定时提醒、日历日记、多笔记本/标签管理、手账画布、OCR、AI、联网同步、账户、云端备份、协作、多端客户端、PDF 解析、手写压感、正式签名发行或正式应用商店上架。

不额外引入新 Gradle 功能模块或数据库大重构，除非有实测必要并经独立小步审阅。源代码许可证仍需维护者另行决定，本阶段不擅自添加最终 LICENSE。真实硬件性能未跑之前，不用模拟器数据替代手机指标。

## 10. 实施顺序、测试门禁与合并条件

1. **B0：迁移先行**。先补齐真实 v1 fixture、Room v1→v2 迁移与旧数据守恒测试；导入 v1 备份仍通过；提交 v2 schema。此步稳定后才改业务 UI。
2. **B1：中文搜索**。先完成数据查询/边界测试，再增加 Compose UI；生成 10k 合成笔记，记录性能、查询计划和结果正确性。
3. **B2：回收站**。覆盖保存队列与软删除竞态、恢复与永久删除、关联附件引用，保证撤销和失败提示。
4. **B3：本地图片**。实现安全 URI 导入与私有目录、复制/重启/删除的完整生命周期，限制图片尺寸/体积/内存。
5. **B4：完整 v2 备份**。带上图片、删除状态、主题；用真实 SAF 接口回归导出→新库导入、重复导入、冲突、损坏、空间不足、取消和中断。
6. **B5：密码保护**。先做依赖与格式安全审阅，再实现并测试错误密码/认证失败/互操作，不以自制密码算法替代。
7. **收尾**。冻结全部变更的源码 SHA，执行模型/Room、Lint、手机/平板 Compose 与进程重建、升级迁移、备份恢复、安全/隐私与必要设备测试，审阅结果及新旧数据合同。通过后再单独决定 Ready/合并。

**CI 与证据约束**：唯一普通入口仍为 `.github/workflows/ci.yml`，标准官方 GitHub-hosted `ubuntu-24.04`；普通 PR 只读、不接触正式签名、没有 Actions Artifact/持久缓存/自托管 Runner。纯文档变更只跑轻量门禁；源码变更按相关度跑测试。确切记录 source SHA、tested merge SHA、run/attempt、通过/失败/未执行；关键证据归档并远端读回后再称交付。长 Runner job 启动后由维护者监控，结束后再继续审阅，不进行聊天内持续轮询。

- [ ] 从 PR-A `Room v1` 实际数据库升级成功，原始文本、ID、修订和主题不丢；无破坏性迁移。
- [ ] 中文/英文搜索与回收站在手机、平板窗口及 10k 合成数据上正确，性能报告注明真实测试条件。
- [ ] JPEG/PNG/WebP 选择、复制、重开、共享引用、软删除/永久删除的闭环测试通过，文件系统异常不会造成静默数据损坏。
- [ ] v1 备份向后兼容；v2 明文及密码保护备份与恢复往返一致，附件哈希、删除状态、冲突副本和设置均有实际证据。
- [ ] 错误密码、损坏、路径穿越、压缩炸弹、取消、断电/进程终止模拟及空间不足测试没有破坏原始数据库。
- [ ] 最终源码的官方 CI 必要检查和独立证据流程完成；用户手工确认至少一次系统文件选择器的完整 v2 导入/导出，未测真机项目明确标注。
- [ ] 审阅后才合并，`main` 不直推功能代码；本阶段只开一个活动 PR。

**冻结变更规则**：新增/删减交付目标、改变 v1/v2 兼容承诺、降低隐私与数据安全边界，必须先显式修订本文件并经审阅，不能悄悄在代码中改变。本次目标冻结不等于已经完成任何一项 B0–B5。
