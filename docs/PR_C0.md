# PR-C0：单调时钟番茄钟与简洁专注页（开发分支）

- 基线：已合并 PR-B 的 `main` 提交 `f513b8a29058264c2c48d5704195dd4375949e75`。
- 工作分支：`feat/pr-c0-focus-timer`。
- 目标：提供独立于笔记编辑器的原生 Compose 专注页，以及可暂停、继续、重置、退出重开后恢复的倒计时状态机。此阶段不建设提醒、统计、待办、动画或手写系统。

## 行为合同

1. 固定可选阶段：专注 25 分钟、短休息 5 分钟、长休息 15 分钟。当前运行/暂停时不能误切阶段；重置需要明确确认。
2. **计时依据**是 Android `SystemClock.elapsedRealtime()`（包含设备休眠时间），绝不依赖每秒自减或 `System.currentTimeMillis()`。每次操作原子保存到独立 Preferences DataStore；前台 1 秒更新仅是渲染采样，不逐秒写磁盘。
3. 保存单次开机标识 `Settings.Global.BOOT_COUNT`。同一次开机内进程被杀，恢复时用单调时钟锚点补齐已过去的时间；若开机标识变更、不可读或时钟倒退，运行中的阶段进入 **中断**，绝不把关机时间计作已完成专注。暂停状态允许在新一次开机手工继续剩余时间。
4. 倒计时到零显示“本段已完成”，但 **不会发系统通知/声音提醒，也不会产生历史统计**；这两项留待 C2/C3。没有精确闹钟权限请求、后台保活或服务器依赖。
5. 计时状态是本机临时设备状态，不作为跨设备备份恢复时自动重启的资料；此阶段不新增 Room 数据表或修改已有 PR-B 的备份合同。
6. DataStore 保存失败时不向用户报告成功；如果状态文件无效则阻止操作并报告，不能把旧笔记/备份或计时状态静默清零。

## 针对性验收

- 纯 Kotlin：开始、暂停/继续、固定阶段、完成幂等、同开机重启恢复、开机次数变化/单调时钟倒退中断、时间区/墙钟变化无影响、无效持久化拒绝。
- API35 迷你 Compose 门禁：手机与平板各一次专注页进入、暂停、Activity 重建、继续、重置；验证状态不会因 UI 重组倒退。
- `app:lintDebug`、`app:assembleDebug`、`app:processReleaseMainManifest` 与无网络权限检查。PR-B 的 AES/备份回归已由精确 HEAD `22778b18` 测过；C0 仅新增计时模块及导航，当前 PR 不重复耗时的 B5 互操作/API26/全量 Room 模拟器矩阵。
- 真机手工再测：熄屏 2 分钟、系统切后台、强制结束后重开、设备重启、手机时间调整、横竖屏。真实手机操作和性能均未执行，不得因模拟器绿灯而声称通过。
