# B4.2b 手机 SAF 手工验收清单（候选版）

**用途**：B4.2b CI 成功后由维护者本人在测试手机操作；仅处理合成或可再生资料，不使用唯一的重要笔记。不得跨临时 CI Debug 签名强行覆盖安装旧 PR-A APK。

## 测试前准备

- 确认安装同一应用签名身份与匹配的 applicationId；签名不同的测试 APK 不可作为覆盖升级证据。此次手机测试可独立新装到测试配置，但不等于已验证真实 PR-A→PR-B 覆盖升级。
- 创建两条合成中文笔记，至少一条含换行、Emoji，修改后观察“已保存”；将其中一条移入回收站。
- 设置深色主题并记录原有笔记、回收站状态。该阶段未开放图片创建按钮，图片内核测试需以独立 Android 仪器测试作为证据，不能假称用户能在界面添加图片。

## 操作步骤与实际结果

- [ ] 打开 **设置与备份**，可看到“导出完整备份（ZIP v2）”“导入完整备份（ZIP v2）”以及两个仍可用的旧 JSON v1 入口。UI 窗口有明显明文备份警告。
- [ ] 点击 ZIP 完整导出，确认有明文风险弹窗。首次点击取消，系统没有创建新文件，界面没有显示“备份完成”。
- [ ] 再次导出，系统文件选择器选择**本机文件夹**，文件名后缀为 .xuaney.zip。完成后应用反馈“关闭并读回校验”；使用系统文件管理器确认 ZIP 文件存在。
- [ ] 点击 ZIP 完整导入，系统 OpenDocument 选择刚导出的文件；显示待恢复正常/回收站笔记数、图片数量、主题和少量合成标题。点击“取消”，原资料保持。
- [ ] 再次导入并点击“确认恢复”。相同记录应跳过，不重复生成副本；原有回收站笔记及深色主题保留。
- [ ] 修改一篇本地笔记，再次导入同一 ZIP：原文不被覆盖，冲突以“恢复副本”出现。再次导入不应无限新增同内容副本。
- [ ] 对非 ZIP、截断、被修改的文件执行导入：应明确提示未通过校验，不清空笔记或回收站，不错误报告成功。
- [ ] 旧 JSON v1 文件仍可以单独从旧入口恢复；当回收站非空，旧版 JSON 导出仍须明确拒绝不完整备份。
- [ ] 旋转屏幕、切换后台后重开，笔记正文、回收站及设置仍存在；确认手机无 INTERNET/ACCESS_NETWORK_STATE 等网络权限。

## 特别记录

请记录型号、Android 版本、APK 的相同签名身份、测试实际结果及选用的 SAF 提供者（本地或第三方），必要时使用脱敏截图。文件提供者不支持关闭后重读的情形必须显示失败，而不能声明备份完整。第三方云盘读写、磁盘空间不足、杀进程中断、已签名的跨版本覆盖升级和独立平板真机需要另列测试；不可因本清单而冒称已经覆盖。
