## 缺陷与针对性修复

旧脚本假定 `connectedDebugAndroidTest` 完成后仍保留应用和测试 APK，然后直接启动 Activity。这不是可依赖的测试前置条件。手机 UI 测试已成功启动同一个 Activity，所以不据此修改生产 Activity 名称或应用代码。

新 `tools/post_test_probe.sh` 在每个窗口的 Gradle 测试结束后，显式安装同一次构建的 debug APK 和 androidTest APK；检查两个包及 instrumentation 的注册，再执行独立的 seed → force-stop → verify，并核查进程确实终止。seed 与 verify 之间禁止重装、清数据或运行 Gradle，避免制造“重开找回”的假阳性。ADB 的退出码与 instrumentation 成功摘要均检查；0 退出码不能掩盖测试断言失败。

两次安装不重新编译；前后核对 APK SHA-256。共用一个模拟器的设备 Gradle 任务改为 `--no-parallel`，避免多个模块同时安装/清理。没有增加 Runner、镜像矩阵、Artifact、缓存、写权限，也没有移除原有测试或放宽其断言。

`tools/test_device_probe.py` 的 12 项本地模拟 ADB 契约测试通过，覆盖安装前置条件、两种窗口、安装/包/runner/Activity 错误、断言失败但 ADB 返回 0、非零退出码不被 tee 吞掉、force-stop 检查、APK 改动与缺失、空截图。**这是脚本回归，不是真机或 Android 功能验收。**

官方命令行测试文档明确要求直接 `adb am instrument` 前先安装主 APK 和测试 APK：<https://developer.android.com/studio/test/command-line>。
